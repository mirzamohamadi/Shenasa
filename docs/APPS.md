# Apps (OAuth2 / OIDC clients)

Operator guide for `#/apps`. Every endpoint below is the Kanidm 1.10 / 1.11
REST surface (`libs/client/src/oauth.rs`, `server/core/src/https/v1.rs`).
Shenasa does not invent a second contract.

Requires the **`idm_oauth2_admins`** role. Writes also need an active
**write window** (top-bar **Unlock write access**). `idm_admins` has no
OAuth2 power.

---

## 1. What an “App” is

One Kanidm **OAuth2 resource server** = one application that signs users
in through this identity domain.

| Kind | Create route | Secret | Typical use |
| --- | --- | --- | --- |
| **public (PKCE)** | `POST /v1/oauth2/_public` | None. The app must use PKCE S256. | Browser SPA, native, mobile |
| **basic (secret)** | `POST /v1/oauth2/_basic` | Generated by Kanidm. Never sent on create. | Server-side confidential client |

Type is **immutable**. Kanidm has no convert-public-to-basic API. Create
the right kind, or delete and start again (SSO for that `client_id` dies
the moment you delete).

---

## 2. Create — what the form does (and what it does not)

**New client** fields are the same for public and basic. That is not a
UI bug. Kanidm’s create body is the same four attributes either way:

```
attrs:
  name                      → OIDC client_id (lowercase INAME)
  displayname
  oauth2_rs_origin_landing  → post-login landing URL (https only)
  oauth2_strict_redirect_uri: "true"
```

There is **no secret field** and **no secret tab** on this form. Kanidm
never accepts a caller-chosen secret (`idm_oauth2_rs_basic_create` does
not take one). Changing the dropdown only picks `_public` vs `_basic`.
The live note under the dropdown says so.

After **Save**, Shenasa:

1. POSTs the create body.
2. PATCHes `oauth2_rs_origin: [landing]`. Create does **not** write
   origins. With strict redirect on (the default), authorize rejects the
   callback until at least one origin exists. This PATCH is the same
   step `deploy/bootstrap.sh` / `test/integration.sh` perform.
3. Sets the URL to `#/apps/{name}` so refresh stays on the detail page.
4. If the client is **basic**, GETs `/v1/oauth2/{id}/_basic_secret` and
   opens the reveal modal once. Copy it into a vault. Later use
   **Reveal basic secret** on the detail page — the value can be read
   again; it is not a one-shot like a service-account API token.

If step 2 fails, the client still exists. A warning tells you to add the
landing URL under **Redirect origins** yourself.

Landing must be `https://…`. Plain `http://` is rejected here (Kanidm
does not accept it for this attribute). `http://localhost` is not a
landing URL.

## 3. Detail page — each control

### Identity

- **Client ID** — `name`. Immutable after create.
- **Display name** / **Landing URL** — **Edit**. Edit does **not**
  change type and does **not** rewrite the origin list.
- **UUID** — server assigned, read-only.
- **Delete** — `DELETE /v1/oauth2/{id}`. Sign-in for that client stops
  immediately. Confirm dialog is mandatory.

### Strict redirect URI

Checkbox → `PATCH` `oauth2_strict_redirect_uri` `"true"` / `"false"`.

- **On (default, keep it):** the `redirect_uri` in the authorize request
  must match an entry in **Redirect origins** exactly.
- **Off:** Kanidm accepts URIs under the origin prefix. Weaker. Only for
  a legacy app that cannot send a stable callback.

### Redirect origins

Attribute: `oauth2_rs_origin` (multi-valued https URLs).

Shenasa replaces the whole list on each add/remove (`PATCH`). The
official CLI appends via `POST /v1/oauth2/{id}/_attr/oauth2_rs_origin`
(`kanidm system oauth2 add-redirect-url`). Same attribute.

Add the **exact** callback the application sends as `redirect_uri`. If
that is not the landing URL, add it as a second origin. Missing slash,
`http` vs `https`, or the wrong host is the usual “Redirect URI
mismatch”.

An empty list with strict **on** means authorize will fail.

### Scope maps

`POST /v1/oauth2/{id}/_scopemap/{group}` with a **bare JSON array** of
scope strings, e.g. `["openid","profile","email","groups"]`.

`DELETE /v1/oauth2/{id}/_scopemap/{group}` removes that group’s map.

The `{group}` path segment is a name or SPN; the server resolves it.
Writing the raw `oauth2_rs_scope_map` attribute is not a supported
client path.

Without a scope map, a user can often still complete authorize, but the
token will not carry the scopes/claims the application needs (`groups`
in particular).

**Supplementary scope maps** (`_sup_scopemap/{group}`) are extra
scopes/claims Kanidm may ask the user to approve. Same body shape.

### Claim maps

`POST /v1/oauth2/{id}/_claimmap/{claim}/{group}` — bare array of values.
`DELETE` the same path.

Example: claim `department`, group `it-admins`, values `engineering
platform` → JWT claim `department` for members of that group.

### Basic secret

Shown only when the entry’s class includes `oauth2_resource_server_basic`
(or the hidden `oauth2_rs_basic_secret` attr is present). Public clients
get a sentence, not a disabled button.

`GET /v1/oauth2/{id}/_basic_secret` → JSON string. Treat it as a
password for that application.

## 4. How Shenasa itself signs in (the template)

`deploy/bootstrap.sh` creates the **public** client `shenasa_admin_ui`:

- landing / redirect = `https://<domain>/admin/`
- strict = true
- scope maps for the admin role groups → `openid profile email groups`

Shenasa’s SSO uses Authorization Code + PKCE S256 against
`<origin>/ui/oauth2` (never `/v1/oauth2`, never the American-spelled
`/oauth2/authorize`). Tokens go to `<origin>/oauth2/token`. Discovery:

```
<origin>/oauth2/openid/<client_id>/.well-known/openid-configuration
```

Kanidm’s OIDC access token is **not** valid on `/v1`. After SSO, REST
calls use the web-session cookie. That is why Shenasa’s own client is
public, not basic.

Copy this pattern for other public SPAs. Use **basic** only when the
application is a confidential server that will present a client secret
at the token endpoint.

## 5. Adding a third-party OIDC application

1. Unlock write access.
2. Confirm you are in `idm_oauth2_admins`.
3. Apps → **New client**.
4. Pick **public** or **basic** (read the live note; fields will not
   change).
5. Client ID = the `client_id` the app will send (lowercase,
   `^[a-z][a-z0-9-_.]{0,63}$`).
6. Landing URL = where users should land after sign-in (`https://…`).
7. Save. For basic, copy the secret immediately.
8. On the detail page, add every exact `redirect_uri` the app uses if it
   differs from landing.
9. Add a **scope map** for each group that should use the app. Typical
   OIDC set: `openid profile email groups`.
10. Point the application at:

    | Setting | Value |
    | --- | --- |
    | Issuer / discovery | `https://<idm>/oauth2/openid/<client_id>/.well-known/openid-configuration` |
    | Authorization | `https://<idm>/ui/oauth2` |
    | Token | `https://<idm>/oauth2/token` |
    | Client ID | the name you created |
    | Client secret | only for basic; from the reveal modal |
    | PKCE | required for public |

11. Sign in with a user who is in a mapped group. If authorize succeeds
    but the app has no roles, the scope map or the `groups` scope is
    missing.

Do **not** share one OAuth2 client across unrelated applications.
Kanidm’s project will not support that; it breaks the OAuth2 security
model.

## 6. What the UI will not do

| Want | Reality |
| --- | --- |
| Type a secret on create | Not accepted by Kanidm |
| Convert public ↔ basic | No API |
| Image / logo upload | `_image` exists upstream; not wired |
| Device-flow toggle | API exists; not wired |
| Disable PKCE on a public client | Possible upstream; Shenasa does not offer it (insecure) |
| Guess scope maps | You must add them |

---

## 7. Failures

| Symptom | Cause |
| --- | --- |
| Dropdown “does nothing” | Fields are supposed to stay the same. Read the live note. |
| No secret after create | Public client, or you closed the modal without copying (use **Reveal**). |
| Redirect URI mismatch | Origin list does not contain the exact callback; or strict is on and you only set landing on a client created before this release. Add the URI. |
| 403 on every Apps write | Read-only session, or missing `idm_oauth2_admins`. |
| Token has no groups | No scope map, or the user is not in a mapped group, or the app did not request `groups`. |
| Discovery 404 | Client name typo, or the client was deleted. |
| Create 400 | Name already exists, or landing is not https. |

Live contract check on a real server: `bash test/integration.sh` (needs
Docker). It creates a public client, a basic client, reads
`_basic_secret`, PATCHes origin, and hits discovery.
